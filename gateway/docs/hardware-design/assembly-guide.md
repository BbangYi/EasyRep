# HabitatOS 1차 물품 조립 안내

**실물 확인 전 검토본 · 2026-10-04.** 최초 HWP 12품목과 보유 Raspberry Pi 5가 기준입니다.
현재 물품은 미조립입니다. 연결 관계 대조는 실물 조립·통전 합격을 의미하지 않습니다.

[한 단계씩 보는 그림 안내](assembly-guide.html) · [검증 결과와 남은 항목](assembly-verification.md)

이 파일은 scripts/build_assembly_guide.py에서 연결표·핀맵을 대조하여 생성합니다.
그림·단계 이동은 장치를 제어하지 않습니다. 실제 조립 완료 여부를 자동 판정하지 않습니다.

별도 보유: Raspberry Pi 5. 전원·헤더·케이블·공구·동봉 저항은 실물 확인 대상입니다.

## 00 · 범위와 현재 상태 확인

준비: 최초 HWP 12품목 + 보유 Pi 5

1. 이 안내서는 센서 노드 3대와 USB 카메라의 작업대 검증을 위한 검토본입니다.
2. 실물 사진·홀 배열·헤더 방향·전원 측정은 아직 확인되지 않았습니다. 각 확인 단계의 조건이 맞을 때만 다음 조립을 진행합니다.
3. 기존 R8의 Waveshare 카메라·SAFE R15·구형 설치 스크립트를 이 안내서와 섞지 않습니다. 이 안내서는 장치에 명령을 보내지 않습니다.

**확인할 결과:** 최초 HWP 확보품과 이번 작업 범위를 대조하고, 사육 동물이 없는 작업대를 준비합니다.

**진행 조건:** 다른 모델 또는 다른 핀 배열이면 대응 그림을 확정할 때까지 해당 부품을 연결하지 않습니다.

## 01 · A·B·C 부품을 분리하고 라벨 붙이기

준비: 노드당 ESP32 1, SEN0331 1, DS18B20 2, 분기기판 1

1. A = ESP32-001 / CAGE-001 / RGB-001, B = 002, C = 003으로 구분합니다. 실제 매장 설정과 다르면 설정에 맞춰 대응표부터 수정합니다.
2. 첫 프로브는 DS-A1/B1/C1, 두 번째는 DS-A2/B2/C2입니다. GPIO13 프로브는 화면 T2, GPIO14 프로브는 화면 T3입니다.
3. SEN0331이 화면 T1(온도)·RH1(습도)을 제공합니다. 물리 배선명 T1D를 화면 T1로 읽지 않습니다.
4. Pico H는 확보품으로 보관합니다. 이번 센서 노드 조립에는 연결하지 않습니다.

**확인할 결과:** 세 부품 묶음에 중복 ID가 없고 각 프로브 양끝에 같은 ID를 붙였는지 확인합니다.

**진행 조건:** 입고품 수량과 실제 모델이 HWP와 다르면 먼저 기록합니다.

## 02 · 공구·전원·커넥터 확인

준비: 테스터와 배터리, 인두·받침, 탈피기·니퍼, 절연재, 4.7kΩ 저항 2개/노드

1. 납·테스터를 구매했다는 사실만으로 인두·배터리·헤더·USB 데이터 케이블까지 있다고 간주하지 않습니다.
2. 4.7kΩ 저항 동봉 여부와 실물 허용오차를 확인합니다. F/F 소켓은 확인된 수핀에만 체결합니다.
3. Pi 5 전원, ESP32 Micro-USB 전원, UH505 어댑터를 각각 라벨로 확인합니다. ESP32에는 USB와 5V/3V3 핀 전원을 중복 공급하지 않습니다.
4. ESP32와 센서 사이에는 공통 GND가 필요합니다. Wi-Fi로 통신하는 Pi와 ESP32 사이에는 이 설계상 별도 GPIO·접지선을 추가하지 않습니다.

**확인할 결과:** 필수 공구와 실제 맞물리는 커넥터, 정격이 확인된 전원을 준비합니다.

**진행 조건:** 커넥터 성별·전압·극성이 확인되지 않으면 전원을 연결하지 않습니다.

## 03 · 실물 앞뒷면과 핀 이름 확인

준비: ESP32·SEN0331 앞뒷면

1. ESP32 모듈면: 안테나 위, USB 아래를 유지하면 J2가 왼쪽, J3가 오른쪽입니다. 뒷면은 좌우가 바뀝니다.
2. SEN0331 센서면에서 헤더 열을 아래에 두면 VCC·GND·SCL·SDA·INT·RST 순서입니다. 실제 실크와 제조사 사진을 대조합니다.
3. GPIO21은 21번째 핀이 아닙니다. GPIO21=J3.6, GPIO22=J3.3, GPIO13=J2.15, GPIO14=J2.12입니다.
4. 긴 수핀의 장착면, 미납땜 헤더, 프로브의 3선/4선과 선 역할을 실물로 확인합니다. 다른 색 체계는 추측하지 않습니다.

**확인할 결과:** 확인한 앞뒷면 사진과 핀 이름을 작업 기록에 남깁니다.

**진행 조건:** 그림은 연결 관계를 설명하는 작업도입니다. 실물 장착면·치수·커넥터가 맞지 않으면 작업을 멈춥니다.

## 04 · ESP32 단독 소프트웨어 준비

준비: 센서를 연결하지 않은 ESP32 1대

1. 현재 프로젝트 firmware/cage_node의 센서 전용 펌웨어와 해당 노드의 비공개 config.h를 사용합니다.
2. 보드·포트를 확인하고 컴파일/업로드 결과를 기록합니다. 이 안내서를 만들면서 실제 ESP32에 업로드한 것은 아닙니다.
3. Wi-Fi·MQTT 인증정보는 화면 캡처나 이 문서에 복사하지 않습니다. Pi의 실제 TLS 설정과 노드별 ID를 대조합니다.
4. 115200 시리얼의 기동 메시지와 Pi에서 노드 연결 여부를 확인한 뒤 전원을 분리합니다. 이 단계만으로 센서 정상 판정을 하지 않습니다.

**확인할 결과:** 노드 ID가 맞고 업로드·기동·인증 결과가 기록되어 있어야 합니다.

**진행 조건:** 컴파일·업로드 또는 인증이 실패하면 하드웨어를 더 연결하지 않고 원인부터 해결합니다.

## 05 · 기판에 작업 좌표 표시

준비: 분기기판·자·지워지지 않는 방향 표식

1. 독립 도금홀인지, 공통 패드가 있는지 무전원으로 확인합니다. 자동으로 연결되는 브레드보드가 아닙니다.
2. R8의 조건은 70×90 방향, 2.54mm 피치, 26×31 독립홀 영역입니다. 실제 기판이 이 조건과 일치하는지 먼저 측정합니다.
3. 조건이 맞을 때 부품면 왼쪽 8번째·위 10번째 홀을 작업 A1로 표시하고 A~K, 1~12의 작업 영역을 정합니다. 이는 제조사 인쇄 좌표가 아닙니다.
4. 기판을 좌우로 뒤집으면 뒷면의 A가 오른쪽입니다. 위쪽 표식과 행 번호는 유지합니다. 실제 외곽에서 A1까지 거리를 기록합니다.

**확인할 결과:** 앞뒷면에서 같은 구멍을 가리키는지 확인하고 A1 위치·홀 배열을 기록합니다.

**진행 조건:** 홀 수·피치·공통 패드·부품 간격이 다르면 이 좌표를 강제로 적용하지 않습니다.

## 06 · 전선 임시 배치와 가공 길이 확인

준비: 노드별 연결표·실제 점퍼선·라벨

1. 전원을 모두 분리한 상태에서 실제 장착 위치에 부품을 임시 배치합니다.
2. 각 선의 커넥터 출구부터 연결점까지 경로·굽힘 여유·납땜 꼬리를 같은 기준으로 재고 기록한 후 가공합니다. 그림 길이를 자로 재서 절단하지 않습니다.
3. F/F 점퍼의 기판 쪽을 가공하는 경우 남길 소켓과 선 ID를 먼저 표시합니다. 센서 헤더가 미납땜이면 핀 순서와 장착면 확인 후 납땜합니다.
4. 모든 버스는 납땜면, 저항 몸체는 부품면에 배치합니다. 전선과 저항 리드가 다른 버스에 닿지 않도록 절연·간격을 확인합니다.

**확인할 결과:** 가공 전 길이 기록과 완성 하네스의 단선·잘못된 결선 여부를 확인합니다.

**진행 조건:** 10cm 표기나 기존 PDF의 85mm·73.40mm를 실제 절단 길이로 사용하지 않습니다.

## W01 · 3V3 버스 연결

준비: 확인된 기판·절연 전선 또는 적합한 버스 재료

| 노드 | 선/부품 ID | 출발 | 기판 목적지 | 연결 |
|---|---|---|---|---|
| A | BUS1 | B2 | K2 | 3V3 |
| B | BUS1 | B2 | K2 | 3V3 |
| C | BUS1 | B2 | K2 | 3V3 |

1. B2에서 K2까지 같은 행의 지정 홀을 납땜면에서 연결합니다.
2. 구멍을 납으로 막아 후속 선·저항이 들어가지 못하게 하지 않습니다. 선 ID와 목적지를 확인하고 작업합니다.

**확인할 결과:** 지정 버스의 시작·끝 및 각 지정 패드가 연결되었는지 무전원으로 확인합니다.

**진행 조건:** 연결·납땜·저항/도통 측정 전에는 모든 전원을 분리합니다. 실물 핀/홀 조건이 다르면 중단합니다.

## G1 · 버스만 있는 기판 검사

준비: 테스터·노드별 실제 기록

1. 각 버스 안의 연결을 확인하고, 서로 다른 6개 버스의 15개 조합 사이에 의도하지 않은 연결이 없는지 확인합니다.
2. 이 검사는 저항·전자부품을 연결하기 전입니다. 이후에는 정상 저항 경로가 생기므로 같은 개방 판정을 재사용하지 않습니다.

1. Pi Zero 2 W는 미구매·조건부 영상 송신기 후보이며 최종 선정품이 아닙니다. 검증 기록의 USB·전원·수신 계약과 실제 카메라 호환을 확인한 뒤 1세트 시험 여부를 결정합니다. 현재 Pi는 로컬 V4L2만 지원하며 원격 영상 수신은 아직 구현 전입니다.
2. 두 번째 SEN0331은 현재 펌웨어와 환경 모델의 입력 구성이 지원하지 않습니다. 주소/버스·RH2 채널·모델 입력을 함께 구현한 뒤 연결합니다.
3. 중앙 분무 ESP32·펌프·밸브·독립 차단부는 실제 모델·압력·기동 전류·회로가 확정된 별도 조립 단계입니다. 센서용 GPIO에 펌프 전원을 연결하지 않습니다.
4. 기존 Pico/SAFE R15 도면에서 이름만 바꿔 새 분무 회로로 사용하지 않습니다. 물통·배관·보호함의 길이와 천공 위치도 실측 대상입니다.

**확인할 결과:** 추가 부품 목록·회로·지원 펌웨어·개별 시험 결과가 맞을 때 확장 조립도를 확정합니다.

**진행 조건:** 이 안내서에는 미확정 24V 단자별 연결이나 자동 분무 활성화 절차가 없습니다.

## 12 · 1차 조립 결과 기록

준비: 실측 사진·노드별 검사 기록

1. 검증 기록 Markdown의 판정 항목에 실제 결과를 남깁니다. 화면을 끝까지 넘겼다는 사실은 조립 완료가 아닙니다.
2. 문서 연결 대조, 호스트 코드 검사, ESP32 실물 시험, Pi 통합 시험을 각각 구분합니다.
3. GPU의 합성 데이터 예측 응답과 실제 환경 예측 정확도는 별도 결과입니다. habitat gpu-test는 합성 요청이며 실측 성능 증명이 아닙니다.
4. 1차 센서·카메라 합격은 실제 자동 분무·행동 인식·완전한 3D 복원 합격을 의미하지 않습니다.

**확인할 결과:** 부품·노드·배치 버전, 검사자, 날짜, 측정값, 오류 및 수정 내역이 추적 가능해야 합니다.

**진행 조건:** 아직 확인하지 않은 항목은 미확인으로 남깁니다. 생물 사육용 자동 출력은 빈 사육장 검증 이전에 켜지 않습니다.
