## 실제 영상 모델

기존 학습 흐름은 `원본/라벨 검토 → 데이터 분할 검증 → YOLO11n 전이학습 → 독립 시험 이미지 평가 → 영상 검출·ByteTrack 추적 → 검토 영상/관측 JSONL`입니다. 최신 실험 후보는 위의 Grounding DINO·DINOv2·결합 점수 패키지를 선택해 같은 영상 분석 흐름으로 실행합니다. 위치·2차원 이동량·구역 관측 횟수를 출력합니다. 별도 관찰 실험실에서 검토된 개인 정상 기록 비교를 구현했습니다. 행동 분류·질병 진단·외부 이상 알림과 실제 사육장 검증은 아직 없습니다.

### 설치와 실행 환경

수집기에는 기존 표준 라이브러리 환경을 유지합니다. 영상 학습에만 별도 환경을 사용합니다.

```sh
python3 -m venv .venv-vision
.venv-vision/bin/python -m pip install -r requirements-vision.txt
.venv-vision/bin/python -m behavior_recorder.vision doctor
```

Windows GPU PC에서는 Python 3.12와 프로젝트 파일을 준비한 뒤 다음을 실행합니다. 설치기는 이 폴더의 `.venv-vision`만 사용하며 PyTorch 2.8.0/CUDA 12.8과 torchvision 0.23.0을 공식 배포처에서 설치합니다. 설치·학습·평가 중에만 Windows 자동 절전을 막으며 작업 종료 후 반환합니다. 화면 절전과 영구 전원 설정은 그대로 유지합니다.

```powershell
py -3.12 scripts\setup_vision_windows.py
.venv-vision\Scripts\python.exe -m behavior_recorder.vision doctor
.venv-vision\Scripts\python.exe scripts\check_vision_worker.py --device 0 --weights data\weights\yolo11n.pt --output data\worker-check-01
```

`check_vision_worker.py`는 빈 입력으로 GPU 계산·역전파·공식 가중치 추론·추적 라이브러리를 확인합니다. 동물 학습이나 성능 평가를 수행하지 않습니다. Mac에서는 `--device cpu`로 짧게 실행할 수 있습니다. `extract`와 `infer`는 FFmpeg/ffprobe도 PATH에 필요합니다. Windows GPU 작업에서는 FFmpeg/ffprobe가 있는 프로젝트 도구 폴더를 작업별 PATH에 추가해 실제 영상 디코딩·탐지·추적·MP4 인코딩을 검증했습니다. 일반 터미널에서 직접 실행할 때도 FFmpeg/ffprobe의 PATH 설정이 필요합니다. Windows의 수집기 쓰기는 지원하지 않으며 Linux/Pi 또는 WSL을 사용합니다. Windows 모델 파일은 원자적 교체를 쓰지만 POSIX 디렉터리 fsync와 같은 정전 내구성을 보장하지 않습니다.

사전학습 가중치는 [공식 YOLO11n 배포 파일](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11n.pt)을 사용합니다. 다운로드한 `.pt`는 신뢰하는 출처여야 합니다. SHA-256 검사는 파일 변조 확인이며 임의의 모델 파일을 안전하게 만드는 검사가 아닙니다. 설치 버전은 `requirements-vision.txt`, 실제 환경은 각 실행의 `environment.json`에 기록합니다. Ultralytics 배포 조건은 [공식 라이선스 안내](https://www.ultralytics.com/license)를 참고하세요.

### 데이터 준비

YOLO/CVAT의 `images/train`, `images/val`, `images/test`와 대응 `labels/` 또는 Roboflow의 `train/images`, `valid/images`, `test/images` 구조를 받습니다. 라벨은 `0 중심X 중심Y 너비 높이` 정규화 좌표입니다. 클래스 0의 의미는 데이터 계획의 `species`와 일치해야 합니다. 현재 다종 탐지 실험은 `lizard`, 크레스티드 전용 템플릿은 `crested_gecko`입니다. 빈 라벨 파일은 보이는 도마뱀이 없다고 검토한 사진에만 씁니다. 종별 모델로 바꿀 때는 이름만 바꾸지 말고 각 사진의 종과 박스를 검토해야 합니다.

```sh
.venv-vision/bin/python -m behavior_recorder.vision init-dataset \
  --root data/imported --source-url '원본 데이터셋 URL' \
  --license '출처에 명시된 라이선스' --attribution '제공자' --output data/review-plan.json
```

생성된 계획은 미검토 상태입니다. 각 이미지에서 박스와 종을 확인하고 `reviewer`, `review_method` (`human`, `publisher_annotations`, `assistant`), `species_confirmed`를 기록합니다. AI 검토를 사람 검토로 표시하지 않습니다. 검토 방법별 개수도 결과에 남깁니다. `group_id`는 같은 촬영/원본 영상 및 그 파생 이미지 전체에 동일하게 부여합니다. 연속 프레임을 무작위로 학습·평가에 섞으면 안 됩니다. 원본 관계를 모르는 묶음은 같은 그룹에 두거나 제외하고 별도의 독립 촬영 데이터를 확보합니다.

`split`은 `train`, `val`, `test` 중 하나이며 원본 그룹은 하나의 split에만 속해야 합니다. 클래스·박스 범위·중복 픽셀·파일 해시·출처·검토 누락을 검사합니다. JPEG 재압축·크롭 같은 유사 이미지와 동일 개체 여부까지 자동 판별하지는 않으므로 그룹 검토가 필요합니다.

```sh
.venv-vision/bin/python -m behavior_recorder.vision prepare \
  --root data/imported --plan data/review-plan.json --output data/datasets/crested-v1
.venv-vision/bin/python -m behavior_recorder.vision check --dataset data/datasets/crested-v1
```

완료된 데이터 디렉터리는 다른 PC로 통째로 복사할 수 있습니다. `dataset.json`의 해시와 목록을 검사하고, 학습기는 실행별 복사본에만 캐시를 씁니다. 미등록 이미지나 바뀐 라벨이 있으면 실행을 거절합니다. 각 split의 양성 이미지 요구는 실행상의 최소 조건일 뿐 충분한 학습량을 뜻하지 않습니다.

카메라가 생기면 보관된 실제 세션을 `extract --session ... --clip ...`으로 연결합니다. 외부 원본 파일은 다음처럼 출처를 직접 선언합니다. 프레임은 원본 타임스탬프와 함께 추출되며 전부 미검토 상태로 남습니다. 원본 파일을 분할한 경우 생성된 `group_id`를 공통 원본 ID로 통일해야 합니다.

```sh
.venv-vision/bin/python -m behavior_recorder.vision extract \
  --video data/original.mp4 --sample-fps 0.2 --provenance real_camera \
  --source-url 'local:recording-001' --license 'owner-recorded' --attribution '촬영자' \
  --output data/label-batch-01
```

### 학습·평가·영상 확인

아래는 Windows GPU PC의 프로젝트 폴더에서 실행합니다. 첫 실행은 `--smoke`를 추가해 160px/1회 학습으로 연결만 검사합니다. 이 결과는 `smoke_only`로 남습니다. 실제 후보 모델은 별도 출력 폴더에서 학습합니다.

```powershell
.venv-vision\Scripts\python.exe -m behavior_recorder.vision train --dataset data\datasets\crested-v1 --weights data\weights\yolo11n.pt --device 0 --epochs 30 --image-size 640 --batch 4 --max-minutes 30 --output data\models\crested-v1
.venv-vision\Scripts\python.exe -m behavior_recorder.vision evaluate --dataset data\datasets\crested-v1 --model data\models\crested-v1 --device 0 --output data\evaluations\crested-v1
```

시간 상한은 배치/학습 회차 사이에 확인하는 소프트 제한이며 마지막 검증·저장 시간은 추가될 수 있습니다. 출력 경로 재사용은 거절합니다. `status.json`이 `complete`인 실행만 후속 단계에서 받습니다. 출력은 `best.pt`, 모델·데이터 이력, 원본 그룹, 실제 환경, 검증 지표를 포함합니다. 시험 데이터가 학습 또는 검증에 노출된 경우 평가를 거절합니다. 시험 결과를 보고 수정한 다음에는 새 독립 시험 데이터를 확보해야 합니다.

```sh
.venv-vision/bin/python -m behavior_recorder.vision infer \
  --video data/original.mp4 --provenance real_camera --model data/models/crested-v1 \
  --config examples/vision.tracking.json --device cpu --output data/inference/clip-01
```

추론 폴더에는 `review.mp4`, `observations.jsonl`, `review-queue.json`, `summary.json`이 생깁니다. 가림·다중 검출·추적 ID 변경·긴 시간 간격 사이의 움직임은 추측하지 않습니다. 검출되지 않은 구간은 정상이나 무활동으로 처리하지 않습니다. 구역은 실제 설치 후 `vision.tracking.json`의 정규화 사각형으로 설정합니다. 박스 중심의 2차원 이동량이므로 실제 이동거리·등반 높이·질병 판단이 아닙니다. `observed`는 모델의 검출 조건을 충족했다는 뜻이며 동물의 실제 존재를 보증하지 않습니다.

추적기 `bytetrack-segments-2.2`는 부분적으로 겹치는 상자들이 각각 이전 상자와 서로 가장 잘 대응하는 경우, 이를 무조건 합쳐진 개체로 처리하던 오류를 수정했습니다. 실제 상자 겹침 기준, 한 상자로 합쳐짐, 이동 급변, 시간 간격과 확인 횟수 조건은 유지합니다. 번호는 계속 영상 안의 연속 추적 구간이며, 장기 개체 신원을 보증하지 않습니다.

검출 실패·연결 모호 장면은 아래 명령으로 간격을 두고 추출합니다. 원본 영상과 같은 출처 그룹을 유지하며, 정답 박스·개체 ID는 비워 둡니다. 사람이 확인하기 전에는 학습용 정답으로 사용하지 않습니다.

```sh
.venv-vision/bin/python -m behavior_recorder.vision export-tracking-review \
  --analysis data/inference/clip-01 --video /path/to/original.mp4 \
  --output data/review/clip-01 --limit 40
```

영상 평가에는 `--selection uniform`으로 영상 전반의 표본을, 추적 연결 평가에는 `--selection consecutive`로 연속 표본을 추출합니다. 기본 `failures`는 실패 장면 수집용이므로 전체 영상의 대표 성능으로 해석하면 안 됩니다. `references.json`의 모든 정답은 미검토 상태로 시작합니다. 기본 `schema_version: 1`에서 `visible`은 픽셀 `xyxy` 박스 1개와 영상 내 개체 ID, `absent`는 빈 박스 목록, `unreviewable`은 판단 불가를 뜻합니다. 검토자와 `human`/`assistant`/`synthetic_fixture`를 기록합니다.

여러 마리를 평가하려면 검수한 파일의 `schema_version`을 `2`로 지정하고, 각 기록의 `reference_boxes`·`reference_identity`를 `reference_instances`로 교체합니다. 예: `[{"identity":"scene-a-gold","xyxy":[10,10,30,30]},{"identity":"scene-a-dark","xyxy":[60,60,90,90]}]`. ID는 한 연속 장면에서 눈으로 확인한 개체 연결이며 생물학적 신원이 아닙니다. 같은 프레임의 ID는 서로 달라야 합니다. `absent`는 `[]`, 장면 전환이나 판정 불가는 `null`입니다. 원본 해시·프레임·PTS·검토 정보는 그대로 필요합니다. 자동 검토 내보내기는 계속 버전 1의 미검수 양식을 만듭니다.

버전 2는 상자와 정답을 일대일로 연결하고, `visible_instance_samples`·`matched_active_instance_samples`로 개체별 관측을 셉니다. 한 마리에 박스 두 개를 붙여도 두 마리를 찾은 것으로 계산하지 않습니다. 서로 다른 검출에 같은 활성 ID가 붙으면 `identity_conflict_frames`에 기록하고 해당 ID 연결을 인정하지 않습니다. 검증 코드의 다중 개체 지원이 탐지 모델의 다중 개체 성능 보증을 뜻하지는 않습니다.

```sh
.venv-vision/bin/python -m behavior_recorder.vision benchmark-video \
  --analysis data/inference/clip-01 --references data/review/clip-01/references.json \
  --output data/review/clip-01/evaluation-v1.json
```

평가는 원본 해시·프레임·PTS를 대조하고, 기존 결과를 덮어쓰지 않습니다. 중복 박스는 오검출, 미검토·판단 불가는 제외로 집계합니다. 첫 대상 지정 모드는 초기 지정 프레임을 제외하고 원래 검출 후보와 선택된 후보를 따로 계산합니다. 추적 연결은 **인접한 분석 표본 둘 다 정답이 있을 때만** 측정합니다. 몇 장의 사진 정답만으로 끊김이 0번이었다고 보고하지 않습니다. `id_changes`는 이 제한된 인접 연결의 ID 변경이며 IDF1/HOTA나 긴 가림 뒤 재식별 정확도가 아닙니다.

종합설계의 현재 내부 일정과 통과 기준은 `data/capstone-20261018/delivery-plan.json`에 있습니다. 목표는 2026-11-29이며 실제 촬영 확보와 검증 결과에 따라 조정합니다. `data/capstone-20261018/`의 두 평가 결과는 이전 3장 AI 정답의 개발 검사를 재현한 것으로, 새로운 현장 성능 증거가 아닙니다.

외부 파일의 `--provenance`는 생산자의 선언이며 생략하면 `unverified_file`입니다. 합성 시험 영상은 `synthetic_test`로 표시합니다. 검토 영상은 읽기 쉬운 크기와 고정 재생 속도로 변환하므로 원본과 재생 길이가 다를 수 있습니다. 원본 좌표·프레임·PTS와 검토 영상의 대응은 `observations.jsonl`에 보존합니다.

### SAM3 윤곽과 기존 탐지기를 함께 실행하는 실험 옵션

`sam3-hybrid`는 저장 영상을 직접 읽어 기존 탐지, SAM3 윤곽 추출, 영역 검증, 추적을 차례로 실행합니다. 선택 규칙 2판은 검출 기준을 넘은 기존 개체 하나와 검증된 SAM3 후보가 명확히 대응할 때 박스를 교체하고, 다른 기존 개체는 유지합니다. 검출 기준 미달 박스는 추적용 참고로 남기되 검증된 후보를 막는 근거로 쓰지 않습니다. 두 확정 검출과 겹치는 후보는 교체에 쓰지 않으며 검증을 통과하지 못한 SAM3 후보를 별도로 추가하지 않습니다. 기본 탐지기 선택은 변경하지 않습니다.

```bash
.venv-vision/bin/python -m behavior_recorder.vision infer \
  --backend sam3-hybrid --model data/models/lizard-sam3-hybrid-v2 \
  --video /absolute/path/to/video.mp4 \
  --config examples/vision.tracking.hybrid.json \
  --output data/sam3-video-new --device mps --threads 1 \
  --provenance public_real
```

현재 옵션은 검증 중인 MPS 환경용입니다. 패키지의 `model-card.json`에 기록한 두 로컬 런타임과 모델 파일이 필요합니다. 기존 탐지기의 Transformers 4.57.1과 SAM3의 5.20.2는 별도 프로세스에서 실행하므로 같은 환경에 덮어 설치하지 않습니다. GPU 작업을 순서대로 수행하고, 응답 전에 가중치와 위치 캐시를 해제하며 다른 프로세스의 잔류 메모리를 다음 작업의 할당 예산에서 뺍니다.

`lizard-sam3-hybrid-v2`는 기존 가중치와 점수 기준을 그대로 사용하며 선택 규칙만 바꾼 실험 패키지입니다. 이전 결과 재현에는 `lizard-sam3-hybrid-v1`을 사용할 수 있습니다. 관측 기록의 `inference.route_revision`과 패키지 식별자로 사용한 규칙을 구분합니다.

움직이는 카메라의 공개 영상에서는 추적 설정에 `"camera_motion": "background-affine-v1"`을 넣어 배경 이동 보정을 켤 수 있습니다. 기본값은 `off`입니다. 도마뱀 검출 영역을 제외한 배경 특징으로 프레임 간 이동을 구하고, 이미 확인된 동일 추적 번호가 배경 이동 때문에 점프 기준을 넘었을 때만 연결을 유지합니다. 겹치는 개체, 부족한 배경 특징, 장면 전환, 긴 공백은 보정으로 연결하지 않습니다. ByteTrack이 잃은 개체를 다시 식별하는 기능은 아닙니다. [OpenCV 배경 정합 API](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)를 사용하며 새 모델 학습은 필요하지 않습니다.

이 옵션은 추적 검증용입니다. 화면 좌표가 바뀌는 영상의 이동 거리·속도·구역 체류는 `null`로 보류하고 행동 기준 학습에 넣지 않습니다. `camera_motion` 기록에 추정 행렬·일치점·거절 이유가 남고, 보정으로 연결을 유지한 경우 `camera_jump_compensated` 이벤트가 남습니다. 초기 상자를 지정하는 `target_seed`와는 함께 사용할 수 없습니다.

`observations.jsonl`은 원본 프레임·PTS, 선택 전 두 모델의 박스와 점수, 검증 점수, 선택 근거를 보존합니다. `segmentation/frames/`에는 실제 모델 입력, `segmentation/masks/`에는 원본 좌표계의 마스크 배열이 저장되며 관측 기록의 경로·해시·`mask_index`로 연결됩니다. `review.mp4`는 기존 추적 박스 검토 영상입니다. `sample_fps`는 원본 영상에서 분석할 표본 빈도이며 실제 처리 속도가 아닙니다. 실제 카메라 연속 처리, 다중 개체 식별, 건강·이상탐지는 이 옵션의 구현만으로 검증되지 않습니다.

SAM3 후처리 2판은 최종 선택 기준인 결합 점수 0.5 이상 후보만 원본 크기 윤곽으로 변환합니다. `query_filter`에 원래 쿼리 수와 남긴 인덱스를 기록하며, `raw_predictions`는 이 점수 필터 이후의 후보입니다. 점수 0.5 미만 후보의 전체 크기 마스크는 저장하지 않습니다. 모델 가중치와 최종 검출 선택 기준은 같습니다.

가중치 복귀 2판은 동결된 CPU 가중치를 보관하고 GPU 작업 후 같은 CPU 저장 공간을 재사용합니다. 두 프로세스가 보관하는 가중치는 현재 합계 약 1.84GB이며, GPU에서 계산하는 동안에도 해당 CPU 가중치를 유지하는 메모리 비용이 있습니다. `idle_mps.weight_parking_revision`과 `cpu_cached_weight_bytes`에 방식과 보관량을 기록합니다. 학습 가능한 모델에는 적용하지 않으며, MPS 공유 예산 3GB와 응답 전 위치 캐시 해제는 유지합니다. [PyTorch의 가중치 할당 동작](https://docs.pytorch.org/tutorials/recipes/recipes/module_load_state_dict_tips.html#using-load-state-dict-assign-true)을 사용합니다.

### 실제 이상탐지까지의 진행 기준

학습 개선 실험은 [비교 설정](examples/vision.experiment-v2.json)과 [실험 기준·연구 출처](data/research-20261018/protocol.json)에 고정합니다. `optimizer=auto`는 수동 학습률을 무시할 수 있어, 새 실험은 명시적 AdamW·학습률 0.0001을 사용합니다. [공식 추가 학습 안내](https://docs.ultralytics.com/guides/finetuning-guide)의 원칙을 참고하되, 현재 YOLO11 구조에서 backbone은 0–10번임을 확인해 `freeze=11` 조건과 전체 학습 조건을 비교합니다. 숫자 0.0001과 80회 상한은 이 프로젝트의 실험 설정이며 보장된 최적값이 아닙니다.

새 개발 실행은 다음처럼 만듭니다. 같은 `run-id`나 출력 폴더는 재사용하지 않습니다. 기존 게코 모델부터 학습할 때는 `--initial-model`로 부모 모델을 지정해 노출 이력을 승계합니다. 이미 확인한 시험 자료는 `--development-only`로 평가에서 제외하고, 기존 검증 재현율을 유지한 후보만 선택합니다. **새 시험 자료 확보 전에는 이 옵션을 빼서 반복 성능을 독립 검증으로 계산하지 마세요.**

```sh
.venv-vision/bin/python scripts/run_home_vision_job.py \
  --dataset data/datasets/crested-commons-v2r1 \
  --experiment examples/vision.experiment-warm.json \
  --initial-model data/gpu-jobs/crested-commons-seed-01/result/model \
  --development-only --run-id crested-v2-next-run
.venv-vision/bin/python -m behavior_recorder.vision benchmark \
  --dataset data/datasets/crested-commons-v2r1 --model data/models/candidate \
  --split val --confidence 0.4 --device cpu --output data/benchmarks/candidate-val
```

`benchmark`는 IoU 0.5와 고정 신뢰도에서 박스의 정탐·오탐·누락, 음성 사진 오검출 비율을 기록합니다. 중복 박스도 오탐입니다. **사진당 오검출 비율은 영상의 시간당 오탐 알림 수가 아닙니다.** 검증 집합에서만 F1과 음성 오검출로 후보를 고르며, 새 시험 결과를 보고 다음 실험을 조정하면 그 시험 자료도 개발 자료가 됩니다. 전체 실험을 반복할 때는 새 시험 자료를 준비하거나 재사용 사실을 표시해야 합니다.

[공식 데이터 지침](https://docs.ultralytics.com/yolov5/tutorials/tips-for-best-training-results)은 대표 촬영 조건, 일관된 라벨, 배경 음성 예시를 강조합니다. 현재 음성 자료 비중은 오검출 개선을 확인하기 위한 실험 선택이며 실제 사육장의 출현 빈도와 동일하다고 가정하지 않습니다. 새 데이터의 배경 사진에는 다른 도마뱀 종도 포함되므로 `negative`는 **크레스티드 게코 없음**을 뜻합니다.

[DeepLabCut 연구](https://www.nature.com/articles/s41593-018-0209-y)는 전이학습을 이용한 자세 추정, [SimBA 연구](https://www.nature.com/articles/s41593-024-01649-9)는 명시적 행동 주석과 설명 가능한 행동 분류의 근거로 참고했습니다. 이 연구들의 성능을 현재 모델 성능으로 옮겨 주장하지 않습니다. [비어디드래곤 연구](https://arxiv.org/html/2507.17987v1)도 행동 판정이 필요한 물체의 검출 품질에 의존함을 보여 주지만, 다른 종의 사진·행동 라벨을 크레스티드 게코 정답으로 섞지 않았습니다.

### 빠른 행동 분류기 v1

탐지 본체는 개체 위치를 찾고, 행동 분류기는 그 뒤의 추적 시간창을 별도로 분류합니다. v1은 사람이 전 구간을 명시적으로 `moving`·`resting` 등으로 표시한 창의 속도·이동 비율·공간 범위를 표준화해 분류합니다. 따라서 이미지 자세 모델이나 건강 판정기가 아니며, 실제 행동 성능도 아직 측정되지 않았습니다.

추적 창 JSON(`{"windows": [...]}`)과 `labels-export`가 만든 라벨 JSONL을 같은 clip ID로 연결합니다. 라벨 수정 이력은 최신 활성 라벨만 남기고, 부분 가시성·불확실·미라벨 창은 학습 예제에서 제외합니다.

Vision Lab을 쓰는 경우 완료된 영상의 **행동 상태 기록 v1**에서 `이동` 또는 `휴식`을 저장합니다. 이 UI는 사람 검토 이력과 현재 라벨을 로컬에 별도로 보존하며, 추적 품질이 부족한 창은 `관측 불가`만 허용합니다. 탐지·건강 검토와 행동 라벨은 별개이고, 이 입력만으로 모델을 자동 학습하거나 성능을 주장하지 않습니다.

```sh
# 서로 다른 기록 그룹으로 만든 학습/평가용 창을 각각 준비한다.
python3 -m behavior_recorder behavior-examples \
  training-windows.json training-labels.jsonl clip-training training.examples.json \
  --dataset-kind real
python3 -m behavior_recorder behavior-examples \
  heldout-windows.json heldout-labels.jsonl clip-heldout heldout.examples.json \
  --dataset-kind real

python3 -m behavior_recorder behavior-fit training.examples.json behavior-model.json
python3 -m behavior_recorder behavior-evaluate \
  behavior-model.json heldout.examples.json behavior-evaluation.json
```

같은 `recording_id`가 학습과 평가에 동시에 있으면 평가는 거절합니다. 관측불가 창의 추론은 `unobserved`로 출력하고 `resting`으로 추측하지 않습니다. 거리값은 확률이 아니며, 실제 라벨이 없는 합성 검사는 생물학적 성능 근거가 아닙니다.

1. 실제 사육장 영상으로 검출 누락·오검출·가림 구간을 확인하고 라벨을 보완합니다. 공개 사진의 검출 성능만으로 현장 사용을 승인하지 않습니다.
2. 날짜·개체·설치 환경별로 분리한 영상에서 위치, 이동, 구역 점유와 관측 가능 시간을 검증합니다. 이후 필요한 행동만 구간 라벨을 만들고 학습합니다.
3. 개체별 정상으로 검토한 여러 날짜 데이터를 시간대·환경 정보와 함께 모아 정상 기준을 학습합니다. 모델 경고를 자동 정답으로 재학습하지 않습니다.
4. 나중 날짜의 독립 기록에서 오탐 이벤트/시간, 이상 사건 검출률, 탐지 지연, 판단 보류 비율을 확인합니다. 데이터 양은 이 검증과 학습곡선으로 늘려 결정합니다.

2026-10-18 학습 입력은 게코 33장과 음성 9장입니다. 실제 사육장 연속 영상·야간/적외선 촬영·장기간 정상/이상 사건 검증은 없습니다. 사진을 많이 복제하기보다 새 촬영일·개체·사육장·가림·조명 조건과 크레스티드 게코가 없는 구간을 확보해야 합니다. 필요한 총량은 독립 현장 검증과 학습곡선으로 결정합니다.

별도 후보 [크레스티드 게코 117장 데이터셋](https://universe.roboflow.com/uho122-yahoo-co-jp/test-adjyt/dataset/2)은 Public Domain 표시를 확인했으나 다운로드에 로그인이 필요하며, 기존 split은 train 117 / val 0 / test 0입니다. 이번 학습에는 사용하지 않았습니다.

## 구현 범위와 흐름

1. 카메라 측 생산자가 영상 **구간 하나**를 완전히 저장합니다.
2. 파일 SHA-256과 시각·카메라 정보를 담은 `*.capture.json`을 마지막에 확정합니다.
3. 수집기가 원본을 복사하고 체크섬·컨테이너·프레임 PTS를 검사합니다.
4. 불변 파일 묶음을 저장하고 `manifest.json`을 원자적으로 갱신합니다.
5. 원본 재생, 구간 라벨, 센서·열화상 JSONL을 연결합니다.
6. 종료된 세션을 ZIP으로 내보내고 다른 위치에서 검증·재생합니다.

구현된 입력은 `finalized_file`입니다. 한 파일이 한 원본 clip이며, 기본 상한은 **120초 / 128 MiB**입니다. 카메라 장착 후 생산자에서 구간 녹화하도록 연결합니다. USB/CSI/RTSP 드라이버, 장치 녹화 제어, 대형 영상 자동 분할은 아직 구현하지 않았습니다. 파일 수집 시작이 카메라 촬영 시작을 의미하지 않습니다.

같은 세션에 여러 카메라를 넣을 수 있으나 하드웨어 동기화를 가정하지 않습니다. 카메라별 ID, 사육장, 설치·보정 revision을 보존합니다. 설치나 개체 구성이 바뀌면 새 세션을 만드세요.

## 설치

Python 3.10 이상, PATH에 `ffprobe`와 `ffmpeg`가 필요합니다. 화면 재생에는 `ffplay`도 필요합니다. Python 패키지 설치는 없습니다.

```sh
# 프로젝트 폴더에서 실행
python3 --version
ffprobe -version
ffmpeg -version
python3 -m behavior_recorder --help

# 아직 설치하지 않은 경우에만 직접 실행
# macOS: brew install python ffmpeg
# Raspberry Pi OS / Debian: sudo apt install python3 ffmpeg
```

macOS의 로컬 파일 입력과 headless 재생을 검증했습니다. Linux/Pi에서는 아직 실행하지 않았습니다. 파일 잠금에 POSIX `flock`을 사용하므로 Windows 직접 실행은 지원하지 않습니다. 수집 데이터는 복사할 수 있으며 WSL/Linux에서 읽을 수 있는 구조지만 이 조합은 미검증입니다.

## 수집 시작·중지와 장애 복구

```sh
# 세션을 먼저 start한 뒤, 최대 30초 동안 완성된 파일을 확인합니다.
python3 -m behavior_recorder record data/demo --config examples/config.test.json --seconds 30

# record가 끝난 후 세션을 닫습니다. Ctrl-C / SIGTERM도 수집 중단으로 기록합니다.
python3 -m behavior_recorder stop data/demo

# 갑작스러운 종료나 저장 실패가 있었을 때
python3 -m behavior_recorder status data/demo
python3 -m behavior_recorder recover data/demo
python3 -m behavior_recorder verify data/demo
python3 -m behavior_recorder resume data/demo
python3 -m behavior_recorder record data/demo --config examples/config.test.json --once
```

- `--once`는 현재 inbox를 한 번 처리합니다. 일반 `record`의 기본 실행 상한은 30초, 허용 상한은 3600초입니다. 진행 중인 파일 복사·probe는 그 작업이 끝나거나 probe timeout에 도달할 때까지 완료될 수 있습니다. 상시 서비스나 자동 시작을 설치하지 않습니다.
- `record` 시간 종료는 수집 호출만 끝냅니다. 이어서 같은 세션에 수집하려면 그대로 실행합니다. `stop`으로 닫은 세션은 다시 열 수 없습니다. 라벨과 기존 센서 자료의 후처리 가져오기는 가능합니다.
- 한 세션의 쓰기는 한 번에 하나입니다. 다른 터미널에서 저장 중 `stop`을 실행하면 `another writer is active`가 나올 수 있습니다. 수집 터미널의 Ctrl-C로 중단하거나 현재 clip 처리가 끝난 후 `stop`을 실행하세요.
- `recover`는 미완성 `.partial`, manifest 미등록 entry, 임시 manifest를 `quarantine/`으로 이동합니다. **확정 데이터에 자동 편입하거나 삭제하지 않습니다.** 활성 세션은 `interrupted`가 됩니다. 이후 `resume`을 명시적으로 실행합니다.
- 같은 `input_id`·동일 descriptor 재입력은 원본 체크섬을 확인한 뒤 중복 없이 반환합니다. 같은 ID의 내용 변경이나 같은 카메라/recording/sequence 재사용은 충돌입니다. 새 ID로 같은 바이트를 넣어도 `original_video_id`는 동일합니다.
- 원본 삭제 정책은 없습니다. 세션 전체(격리 파일 포함) 용량 상한·디스크 잔여 공간을 검사하고 부족하면 중단합니다. 실패·복구·종료 같은 작은 제어 기록은 데이터 용량 상한 밖에 남길 수 있습니다. 파일시스템 자체가 완전히 차면 실패 기록도 저장되지 않을 수 있으며 stderr와 `.partial`로 확인합니다.
- `SIGKILL`/전원 차단 후 마지막 활성 상태는 확정되지 않을 수 있습니다. 완성 파일 확인 후 `recover`로 운영자가 중단을 확정합니다. 원자적 rename과 fsync를 사용하지만 실제 Pi의 전원 차단·SD카드 내구성은 아직 시험하지 않았습니다.
- archive 가져오기 실패 시 대상 옆의 `.이름-UUID.import.partial`을 남깁니다. 기존 폴더는 덮어쓰지 않습니다. 검토 후 수동 보관·삭제하세요. ZIP의 경로 이탈·symlink·중복 이름·추출 용량을 검사하고 체크섬을 검증합니다. 악의적 파일에 대한 완전한 보안 샌드박스는 아닙니다.

## 입력 계약

생산자는 파일을 쓰는 동안 `.part` 이름을 쓰고, flush/fsync·close 후 최종 `.mp4/.mkv/.mov/.avi`로 rename합니다. **영상 파일 전체를 안정적으로 만든 다음**, 아래 JSON도 임시 이름에서 `name.capture.json`으로 rename합니다. manifest 게시 후 파일과 descriptor를 변경하지 않습니다. 폴더에 `.part`만 있으면 수집하지 않습니다. 원시 H.264 elementary stream이나 플레이리스트는 입력으로 받지 않습니다.

```json
{
  "schema_version": 1,
  "input_id": "producer-generated-unique-id",
  "camera_id": "rgb-01",
  "file": "segment-000001.mp4",
  "sha256": "파일 전체의 소문자 SHA-256 64자리",
  "recording_id": "stable-recording-id-across-segments",
  "sequence": 0,
  "provenance": "real_camera",
  "captured_at": null,
  "capture_clock": {"source": "unknown", "accuracy_ms": null},
  "placement_revision": null,
  "calibration_revision": null
}
```

`file`은 descriptor 기준 상대경로입니다. 절대경로·상위경로·symlink는 거절합니다. 파일 하나에 비디오 스트림 하나만 받습니다. 다른 오디오/부가 스트림은 원본 파일 안에 유지되지만 프레임 인덱스는 비디오만 대상으로 합니다.

`provenance`는 실제 카메라 원본의 `real_camera`, 합성 파일의 `synthetic_test`, 테스트 재입력의 `replay_test` 중 필수 선택입니다. `dataset_kind=real` 세션은 `real_camera`만, `test`는 나머지만 받습니다. 출처는 생산자의 선언이며 수집기만으로 진위를 증명하지는 못합니다. 설정·파일 이름에서 촬영 출처를 추측하지 않습니다.

`recording_id`는 하나의 연속 원본 녹화에 대해 전역적으로 유일하고 안정적인 ID를 사용합니다. 파생 clip으로 분할하거나 다른 세션으로 가져올 때도 유지합니다. `sequence`는 카메라·recording별 0부터 시작합니다. 중간 번호 누락은 `missing_clip_sequence`, 늦게 도착한 clip은 `out_of_order_clip`으로 남깁니다. 누락 기록은 당시 관측이며 뒤늦은 도착으로 삭제되지 않습니다.

현재는 영상 구간이 이미 완성된 파일을 받으므로 센서가 없어도 수집할 수 있습니다. 너무 긴 파일은 오류로 중단합니다. 이후 카메라 생산자에서 구간을 만들 때 인코더 keyframe과 PTS를 함께 확인해야 합니다. 수집기에서 촬영시각을 파일 수정시각으로 대체하지 않습니다.

## 시간·품질 기준

| 항목 | 의미 |
|---|---|
| `pts`, `time_base` | 원본 비디오 presentation timestamp 정수와 유리수 단위. 프레임별 보존 |
| `offset_seconds` | 첫 프레임 PTS에 대한 상대시간. 라벨의 시작·끝 기준 |
| `captured_at` | 생산자가 제공한 첫 프레임의 실제 촬영시각. 모르면 null |
| `capture_clock` | `unknown/device/host_ntp/host_unsynced/operator`, 정확도 ms 또는 null |
| `estimated_capture_at` | 첫 프레임 시각 + PTS 차이. **추정값**이며 프레임별 실측 촬영시각이 아님 |
| `host_received_at` | 완성 파일을 수집하기 시작한 호스트 시각. 파일 구간의 모든 프레임 수신시각이 아님 |
| `host_frame_received_at` | 파일 입력으로 알 수 없어 null |
| `dropped_frames` | 파일만으로 실제 유실 개수를 확정할 수 없어 null |

호스트 시계 동기화를 측정하지 않았으므로 `host_clock.source=host_unsynced`, 정확도 null로 시작합니다. 시각 미제공은 unknown/null로 보존합니다. frame PTS는 FFprobe로 추출하며 best-effort timestamp를 원본 PTS로 바꾸지 않습니다. PTS 누락·역행, 설정된 기대 fps 대비 긴 간격을 별도 JSONL 이벤트로 남깁니다. 간격만으로 실제 drop이나 카메라 단절을 확정하지 않습니다. 마지막 프레임 기간을 알 수 없으면 시간 라벨을 막습니다.

파일 입력의 `source_idle`/`source_resumed`는 새 파일 도착 유무입니다. 실제 단절·재연결을 장비에서 확인했을 때만 다음처럼 관측 기록을 추가합니다. 향후 드라이버는 같은 event 계약으로 보고할 수 있습니다.

```sh
python3 -m behavior_recorder event data/demo camera_disconnected --camera rgb-01 \
  --note '장비 로그에서 단절 확인; 예시 명령이므로 실제 확인 후 사용'
python3 -m behavior_recorder event data/demo camera_reconnected --camera rgb-01 \
  --observed-at '2026-10-08T12:00:00+09:00' --note '장비에서 보고한 재연결 시각'
```

## 센서와 열화상

기본 센서 입력 형식은 [sensors.test.jsonl](examples/sensors.test.jsonl)입니다. 관측시각·Pi 수신시각·단위·quality·revision을 보존합니다. `valid`에는 유한한 수치가 필요하고 나머지 quality 값에는 null이 필요합니다. 소스 `sensor`는 real, `simulation`은 test 세션에만 들어갑니다. 영상과의 연결 키는 사육장·관측시각·revision입니다. 시계 정확도가 확인되지 않은 자료를 강제로 동기화하거나 결측 보간하지 않습니다.

기존 EasyRep의 `telemetry.recorded` record를 **한 줄당 하나의 JSON**으로 저장했다면 다음처럼 가져올 수 있습니다. 원래 payload도 `raw_habitat_record`로 보존합니다. `sampled_at`은 `observed_at`, payload의 `received_at`은 `received_at`, 바깥 `serverReceivedAt`은 별도 필드에 저장합니다. payload에 단위가 없으므로 설정 당시 센서 ID별 단위 파일을 반드시 제공해야 합니다. 서로 다른 단위 구성이면 배치를 나누세요.

```sh
python3 -m behavior_recorder sensors data/real-session telemetry.jsonl \
  --format habitat --units examples/sensor-units.json --enclosure enclosure-01
```

수치 열화상은 [thermal.test.jsonl](examples/thermal.test.jsonl)의 2차원 배열 형식입니다. `thermal_numeric` 카메라만 받고, 원단위 `raw_count/degC/K`, 보정 메타데이터, revision, 결측 null을 유지합니다. 자동 온도 변환을 하지 않습니다. 컬러 열화상 영상은 `thermal_color`로 저장하며, 이를 수치 배열이나 온도 측정으로 해석하지 않습니다. 실제 열화상 장비의 원본 SDK 파일 형식은 아직 미연결입니다.

## 수동 라벨과 BORIS

라벨 시간은 **원본 clip의 첫 PTS가 0초인 상대시간**입니다. 구간은 `[start_seconds, end_seconds)`이며 같은 시각의 POINT 이벤트도 허용합니다. 개체를 알 때만 `--animal`을 지정합니다. 행동 어휘는 관측 가능한 행동부터 정하고, 정지를 수면·질병·스트레스로 자동 해석하지 않습니다. 미라벨은 정상·정지·수면 어느 것으로도 채우지 않습니다.

```sh
python3 -m behavior_recorder label data/real-session "$CLIP_ID" \
  --animal animal-01 --start 0.2 --end 1.2 --behavior moving \
  --visibility partial --certainty uncertain --annotator operator-01

# 수정은 기존 행을 덮어쓰지 않고 새 라벨이 이전 ID를 대체합니다.
python3 -m behavior_recorder label data/real-session "$CLIP_ID" \
  --animal animal-01 --start 0.2 --end 1.1 --behavior moving \
  --visibility visible --certainty certain --annotator operator-01 \
  --supersedes '이전 label_id'

python3 -m behavior_recorder labels-export data/real-session labels.jsonl
python3 -m behavior_recorder labels-import data/real-session labels.jsonl
```

기존 도구를 쓰려면 BORIS에서 원본 하나를 zero offset 미디어 관측으로 열고, 한 observation·한 subject의 **Aggregated events TSV**를 내보냅니다. 수집기의 strict adapter는 `Observation id`, `Subject`, `Behavior`, `Behavior type`, `Start (s)`, `Stop (s)` 헤더를 받습니다. 여러 파일 연속 재생·offset이 있는 관측은 지원하지 않습니다. visibility/certainty는 export에 없으므로 운영자가 명시해야 합니다. 전체 batch에 같은 값이 부여되므로 상태가 다른 행은 나누거나 native JSONL로 개별 작성하세요.

```sh
python3 -m behavior_recorder labels-import data/real-session boris.tsv \
  --format boris --clip "$CLIP_ID" --animal animal-01 --annotator operator-01 \
  --visibility partial --certainty uncertain --boris-zero-offset
```

BORIS export 행 원문을 보존하며, TSV fixture로 parser를 검사했습니다. 실제 BORIS 앱 설치·왕복 동작은 검증하지 않았습니다. native JSONL 내보내기는 수정 이력까지 보존하므로 중복 가져오기가 가능합니다.

## 데이터 구조와 이식성

```text
session/
  manifest.json                 # 버전, 세션/개체/카메라, 확정 entry 목록과 파일 SHA-256
  entries/<transaction-id>/
    record.json                 # clip / sensors / labels / thermal / event 메타데이터
    original.mp4                # clip entry의 원본 바이트
    frames.jsonl                # clip entry의 프레임 시간
    events.jsonl                # clip entry의 시간·순서 이상
    sensors.jsonl               # 해당 kind entry에만 존재
    thermal.jsonl
    labels.jsonl
  .partial/                     # 확정 전 데이터. 독자는 사용하지 않음
  quarantine/                   # 복구 시 격리. 자동 삭제/내보내기 없음
```

JSONL은 불변 batch 파일로 저장합니다. manifest 하나가 확정 지점이므로 영상만 저장되고 로그가 잘린 자료를 정상 데이터처럼 읽지 않습니다. 쓰기는 fsync와 같은 파일시스템 내 rename을 사용합니다. 휴대용 데이터에 inbox 주소·사용자 절대경로·자격증명을 기록하지 않습니다. 사용자가 적는 자유 텍스트와 가져온 원문은 그대로 보존하므로 공유 전 별도로 검토하세요.

ZIP은 확정된 원본·metadata·센서·라벨을 포함하며 무압축으로 CPU 사용을 줄입니다. 별도 DB가 없고 원본과 레코드의 ID는 이동/가져오기 후 그대로입니다. 실패 중간 파일·quarantine·writer lock은 export 대상이 아닙니다. 파일 복사로 통째로 이동하는 경우에는 모두 함께 보관됩니다.

후속 데이터셋은 `animal_ids`, `session_id`, `recording_id`, `original_video_id=sha256:<원본바이트해시>`를 사용해야 합니다. 프레임 단위 무작위 분할은 금지합니다. 추가된 AI 기준 모델은 같은 개체의 이후 기록을 평가하므로 개체를 고정하고 세션·연속 녹화·원본의 분할 간 교집합을 차단합니다. 다른 개체로의 일반화 평가에는 개체까지 분리해야 합니다. 구체적인 학습·평가 범위는 [AI_PIPELINE.md](AI_PIPELINE.md)를 참조하세요.

## Pi 연결 시 첫 작업

`examples/config.pi.json`은 **카메라 미연결 상태**를 명시합니다. 먼저 로컬에서 다음처럼 복사해 준비합니다. Pi에 접속하거나 서비스를 변경하지 않습니다.

```sh
cp examples/config.pi.json local.pi.json
# local.pi.json의 input.inbox를 실제 저장장치 위치로 수정
# 카메라 장착 후 model, placement_revision, calibration_revision, expected_fps 확인
# 실제 파일 생산자 검증 후 connection을 finalized_file로 변경
# 실제 개체 ID와 species를 설정. 종 미확정이면 unknown 유지
mkdir -p data/inbox
python3 -m behavior_recorder start data/pi-first --config local.pi.json
# 카메라가 없으므로 현재 clips는 비어 있어야 합니다.
python3 -m behavior_recorder status data/pi-first
python3 -m behavior_recorder stop data/pi-first
```

카메라가 준비되면 첫 작업은 **Pi에서 짧은 영상 한 구간을 얻어 descriptor와 함께 수집하는 것**입니다. 모델·CSI/USB/네트워크 연결·지원 포맷을 확인한 뒤 그 장비에 맞는 생산자 하나만 붙입니다. 먼저 10초 구간으로 다음을 확인하세요.

- 저장된 영상 재생과 실제 카메라 시야·가림·개체 식별 가능 여부
- 시계/NTP 상태, 실제 capture timestamp 제공 여부, PTS 단위·프레임 누락 보고 가능 여부
- 설치·보정 revision, 카메라 ID, 사육장/개체 소속
- CPU·온도·초당 저장량, 저장 공간 reserve, SD/외장 저장장치 선택
- 단절·재연결·전원 차단 후 파일 finalization/복구
- 수치 열화상이 있다면 단위·결측·보정·원본 SDK 배열 형식

이 확인 전에는 CSI/USB/RTSP 명령을 임의로 설치하거나 테스트 영상을 실제 관측으로 바꾸지 않습니다. 운영 DB·기존 웹앱·장치 제어·GPU/SaaS 배포는 이번 모듈의 범위 밖입니다.

`Start Vision Lab.command` 실행 → **공개 자료 확장 · 도마뱀 공통 탐지**에서 실제 사진과 출처별 기준 박스를 확인합니다. 영상 분석에서도 공개 자료 모델을 별도로 선택합니다. 기존 크레스티드 전용 모델과 탐지 대상이 다릅니다.

- 데이터: `data/datasets/lizard-public-v1/dataset` — 공개 연구 사진 694장 + 기존 게코 양성 사진 55장. 학습 624 / 검증 75 / 시험 50. 이 중 도마뱀 양성 266장, 배경 483장입니다.
- 원본·라이선스·라벨 수량: `data/public-reptile-research-20261018/bearded-metadata.json`, `data/datasets/lizard-public-v1/audit.json`. 소개 글의 숫자와 실제 배포 ZIP 수량이 다릅니다. Zenodo는 CC BY 4.0을 표시하지만 내장 Roboflow 메타데이터는 Private이며, 제3자 사진 권리를 별도로 검증하지 않았습니다. 공개 재배포가 승인된 자료로 간주하지 않습니다.
- 영상: `data/public-reptile-research-20261018/sawit-videos/manifest.json` — 마블드게코 9개, 다른 카메라 스킨크 6개, 총 259.2초. 종 라벨만 있으며 행동·건강 이상 정답은 없습니다. 출처는 SAW-IT-Plus, CC BY-NC-SA 4.0입니다.
- 그룹 분리: 파일 계열·유사 이미지 단위입니다. 촬영 장소와 개체가 완전히 분리된 시험이라는 뜻은 아닙니다. 기존의 종별 음성 사진은 다른 도마뱀을 포함할 수 있어 공통 모델의 음성 자료에 넣지 않았습니다.
- 실제 카메라가 없어도 공개 자료의 탐지 모델과 영상 특징 분석을 개발합니다. 개인 사육장 정상 기준, 건강 이상 성능, 24시간 운영 증거는 별도 확인 대상입니다.

재현할 때 기존 산출물을 덮어쓰지 않도록 새로운 출력 폴더와 실행 ID를 사용합니다.

```sh
.venv-vision/bin/python scripts/import_bearded_research.py \
  --archive data/public-reptile-research-20261018/bearded.zip \
  --metadata data/public-reptile-research-20261018/bearded-metadata.json \
  --commons data/datasets/crested-commons-v3 --output data/datasets/lizard-public-reproduction
.venv-vision/bin/python scripts/run_home_vision_job.py \
  --dataset data/datasets/lizard-public-reproduction/dataset \
  --run-id lizard-public-reproduction --batch 8 --max-training-minutes 12 \
  --experiment examples/vision.experiment-public-v1.json --development-only
```


자체 학습 모델 `lizard-public-v1-02/transfer-frozen`은 사진 개발 검증 75장에서 13정탐·1오검출·9놓침, 별도 사진 시험 50장에서 16정탐·1오검출·13놓침입니다(confidence 0.4, IoU 0.5). 사진 시험의 개체·촬영 장소 독립성은 확인되지 않았습니다. 공개 영상 16개에서는 추적 가능한 검출이 없어 실사용 기본 모델로 승격하지 않았습니다. 공개 사진 수를 늘리는 것만으로 영상 조건의 일반화가 해결되지 않는다는 실패 결과도 보존했습니다.

SAWIT 연구자 제공 YOLOv5s 체크포인트는 별도로 변환해 비교합니다. 우리가 학습한 가중치가 아닙니다. `publisher-model/source.json`에 원본 URL·Git blob·SHA256, `model/conversion.json`에 공식 YOLOv5 v7.0 변환과 수치 일치 검사 결과를 보존했습니다. 외부 체크포인트는 `torch.load(weights_only=True)`와 확인된 공식 클래스만 허용해 읽었습니다. 추론용 TorchScript는 640×640 입력에서 도마뱀 클래스의 objectness×class probability를 사용하며 새 학습을 수행하지 않습니다. 원본 연구의 학습 목록을 완전히 확인하지 못해 `training_inventory_known=false`로 저장하고, 이를 독립 시험에 사용하려 하면 거부합니다. SAW-IT-Plus 영상과의 학습 중복 가능성 때문에 영상 재생 결과는 개발 확인입니다.

2026-10-19 공개 영상 비교 결과: 자체 학습 모델은 16개 영상 모두 추적 가능한 검출이 없었습니다. 연구자 모델은 스킨크 영상 2개에서 일부 표본이 추적 규칙을 통과했고 야간 게코 9개에서는 통과하지 못했습니다. 스킨크 2개를 최대 15fps로 다시 분석해도 품질 조건을 만족하는 5초 행동 구간은 0개였습니다. 따라서 어느 모델도 이 결과만으로 실사용/이상탐지 성능을 승인하지 않습니다. `data/public-reptile-research-20261018/results.json`과 실험실의 공개 영상 결과 카드에서 원본 출처, 두 모델, 분석 빈도와 실패를 확인합니다. 다음 검수용으로 원본 영상별 6장씩 총 96장을 추출했지만 아직 학습 정답으로 승인하지 않았습니다.
