# 단일 프로젝트 정리

2026-10-03 사용자 요청: 중복 압축파일, LiveScene_Analysis, 시험 출력과 임시 프로그램을 삭제하고 한 프로젝트에서 관리한다.

## 운영 구조

**매장당 Raspberry Pi 5 한 대**, 별도 SaaS PC, 별도 GPU PC를 사용한다.
공통 프로그램에 매장 ID·인증정보·사육장 구성·SaaS 주소·GPU 주소를 적용한다.
GPU 서버는 `habitat/gpu`, Pi 클라이언트는 `habitat/compute`에 있다.
**2026-10-07 현재 Pi 운영 릴리스는 `0.4.14-5a9bc13f4f2f`, GPU 운영 소스도 0.4.14다.** Pi health `ok`·MQTT 연결, Pi 핵심 소스 7개와 GPU 소스 9개의 해시 일치, 기존 설정·인증정보·모델 보존을 확인했다. [Pi 설치 확인](../../var/reports/commissioning/software-r15-20261007-pi-014.json), [GPU 적용 확인](../../var/reports/commissioning/software-r15-20261007-gpu-014.json)을 현재 근거로 사용한다. 과거 버전의 검사 횟수나 접속 상태를 이번 배포의 결과로 합산하지 않는다.

관련 Linux 선택 검사 208개·하위 사례 141개와 환경 API 검사 3개·하위 사례 38개가 통과했다. 실제 Pi→GPU CUDA 통합 모의실험은 가상 120분·360응답·75가상 펌프 실행을 완료했고 마지막 상태는 펌프 OFF·밸브 없음·`idle`이다. [검사 범위](../../var/reports/commissioning/software-r15-20261007-checks.json), [통합 결과](../../var/reports/commissioning/software-r15-20261007-integration.json)를 따른다. 이는 전체 회귀검사·실물 ESP/Pico 동작·실측 환경 예측 정확도의 완료 결과가 아니다. 신판 ESP32는 센서형·중앙형 대상 빌드만 통과했고 두 역할의 요청 출력은 잠겨 있으며 업로드하지 않았다.

SaaS의 최근 하트비트 ACK는 `2026-10-07T05:42:44.867608+00:00`, 하트비트 오류는 `null`이다. 이벤트 성공 시각은 `null`, 대기 이벤트는 1개, 서버 최고 순번은 미확인이고 연속성 상태는 `blocked`·`cloud_continuity_unverified`다. [실제 연결 상태](../../var/reports/commissioning/software-r15-20261007-cloud.json)를 따른다. 하트비트 성공을 이벤트 전달 완료로 해석하지 않으며, 원래 순번·UUID·본문 해시를 보존한다.
운영 설치는 현재·직전 복구용 릴리스를 유지하며, 매장별 프로젝트 사본을 만들지 않는다. GPU WSL 기동·유지 설정과 한계는 [GPU 서비스 운영](gpu-service.md)에 기록한다.

## 저장 규칙

- 소스는 이 프로젝트 하나에서 관리한다. 바탕화면에 날짜별 프로젝트나 ZIP을 만들지 않는다.
- 실행 출력은 `var/`, 배포할 때만 필요한 패키지는 `dist/`에 둔다. Git에서 제외한다.
- 테스트 임시파일은 임시 디렉터리에서 실행 종료 시 정리한다. 시험마다 결과 전체를 별도 보관하지 않는다.
- 카메라 영상·학습 데이터·가중치는 실행 장치의 지정된 저장소에서 관리한다. Windows에 다시 복제하지 않는다.
- 하드웨어 제조자료·모델의 대용량 원본을 배포 패키지나 검증 폴더에 다시 복제하지 않는다. 구매 신청서 원본 HWP/XLSX와 사용자가 제공한 원본 ZIP은 보존한다.
- Pi의 0.4.8·0.4.9·0.4.10 전달 `.pyz`와 이전 타이밍 수정 임시 설정 사본은 해당 배포 확인 후 삭제했다. 당시 최종 동기화 후 개발 PC의 프로젝트 `.tmp`를 삭제하고 경로 부재를 확인했다. 파일 581개, 20,509,879바이트를 정리했으며 [삭제 확인 기록](../../var/reports/commissioning/software-r15-20261005-cleanup.json)에 남겼다. 공통 소스·운영 DB·설정·인증정보·복구용 릴리스와 작은 검증 보고서는 보존했다. 이 기록은 0.4.11 임시 파일 정리 완료를 증명하지 않는다.

## 기능 상태

현재 화면은 매장의 사육장 목록에서 카드를 선택해 3D·센서·제어 상세로 이동하며, 새 사육장의 이름·종·형태를 Pi SQLite에 영구 등록한다. 신규 등록은 `pending_setup`인 로컬 프로필이다. 센서·노드·장치 설정이나 SaaS 등록을 자동으로 생성하지 않으며, 실제 설정 전에는 장치 제어를 사용할 수 없다. 카드 표지의 AI 생성 예시 이미지는 실제 촬영·복원 영상이 아니다.

환경 예측은 합성 데이터로 검증한 단계이다. 복원 촬영 위치·학습 스텝 추천 모델과 크레스티드 게코 행동 모델은 아직 학습되지 않았다. 실물 카메라·센서·분무 장치를 연결한 검증도 남아 있다.

2026-10-04에는 외부 PC·휴대폰의 Tailscale 설치 없이 기존 Funnel HTTPS 화면에 접속하는 경로를 확인했다. 이는 아래 0.4.6 당시 기록이며 현재 외부 접속 경로를 대신하지 않는다. 최신 접속 방법과 확인 범위는 [Pi 운영 안내](pi-update.md)를 따른다. 매장 접속 키는 SaaS 계정 로그인과 별개다.

## 0.4.12 배포 검증 — 2026-10-05 (과거)

당시 Pi 운영 릴리스 `0.4.12-76a2b5356b9c`의 설치·서비스 건강 상태 `ok`·MQTT 연결과 GPU 운영 API 소스 0.4.12 적용을 확인했다. Pi 확인 시각은 `2026-10-05T13:13:25.834393+00:00`, GPU는 `2026-10-05T13:13:12.302080+00:00`이다. SaaS 연속성 보호는 같은 서비스의 하트비트를 유지하면서 미확인 이벤트를 차단했다. 당시 하트비트 ACK는 `2026-10-05T13:13:24.986376+00:00`, 하트비트 오류는 없고 이벤트 성공 시각은 `null`이었다. 대기 이벤트 1개의 원래 순번·UUID·본문 해시를 보존했으며 외부 서버의 정확한 순번 확인과 이관은 완료하지 못했다.

R15의 정상 ON이 만든 예약을 안전 오류로 해석해 다음 주기 검사에서 자기 요청을 OFF로
취소하는 버그를 수정했다. 수정 전 0.4.11의 두 상태(`hello_pending`·`hello_active`)에서
`['on']` 대신 `['on','off']`가 발생해 [회귀검사 2개가 실패](../../var/reports/commissioning/software-r15-20261005-active-reservation-baseline.log)했다.
추가 ON의 busy/공용 예약 진입 검사와 현재 요청의 안전 검사를 분리했으며, 정상 자기 예약은
취소 사유에서 제외했다. 센서 오류·상태 핀 LOW·세션/lease 상실·통신 끊김·STOP,
요청 기한·쿨다운과 실제 상태 미확인 원칙은 유지한다. [R15 계약](../protocols/r15-bridge.md).

수정 후 [관련 검사 46개가 1.29초에 통과](../../var/reports/commissioning/software-r15-20261005-active-reservation-tests.log)했고,
전체 검사는 **396개 통과·7개 건너뜀·subtest 231개 통과, 108.99초**였다.
[Pi 실제 배포 기록](../../var/reports/commissioning/software-r15-20261005-active-reservation-deployment.json)은
설치된 gateway/transport 해시 일치, 비공개 설정·인증 파일의 바이트 보존,
대기 이벤트 순번·UUID·본문 해시 보존을 포함한다. 물리 출력과 R15 브리지는 계속 비활성이다.

[GPU 실제 확인](../../var/reports/commissioning/software-r15-20261005-active-reservation-gpu.json)에서
공통 소스 0.4.12, 22:07:56 KST에 시작한 PID 2854·`active/running`·종료 상태 0,
GPU·환경·LiveScene health HTTP 200을 확인했다. Splatfacto 준비·합성 환경 모델·참조
LiveScene 1개를 구분하며, 이번 수정에서 새 학습·렌더·실물 출력 시험은 수행하지 않았다.
GPU 설정·인증정보·기존 3D 모델과 원본은 변경하지 않았다. SaaS 이벤트 충돌은 여전히 미해결이다.
